# HanaWorlds Contracts 1.2.0

Pure public contracts for the single-user local-world MVP. Import from `hanaworlds-contracts`. This is a fresh-install protocol replacement. No prior exports, peer compatibility, state migration, or permission bridge ships in this package. Earlier source and evidence remain in Git and their original run directories.

`spec/local-world/profile.json` is the authored schema and operation source. `src/local/` owns pure relation/geometry validation. `npm run build` generates `dist/local`, `types/local`, `schemas/local`, and current fixtures. Never edit those outputs directly.

Current wires: `session/v4`, `canvas/v6`, `world-adapter/v7`, `painter/v5`, `BUILD/V4`, `ReferenceBrief/v4`, `interaction-surface/v4`; region wires `region-build/v1`, `painter-region/v2`, `world-adapter-region/v2`, `canvas-region/v2`; compiled operations `operations/v3`; target facts `target-facts/v4`; safety profile `safety-profile/v4`; placement proposal `placement-proposal/v1` (1.1); region rollback cause `region-rollback-cause/v1` (1.2). Existing projections retain the `HanaWorlds|contracts@0.4.0|` domain prefix; every changed shape carries a new wire or profile identifier, so old digests cannot match. The sections below 1.1.0 are history and name the identifiers of their time.

## 1.2.0 · cause of a successful region rollback (release 1.2.0)

**Change note (1.2.0, qualified additive minor; every 1.1 value, digest, wire and capability id unchanged):** a successful whole-region rollback can state why Canvas restored. `RegionCommitResult.rollbackCause` (`FailureDetail {error, guardRefusal}`) is optional, has no null form, and appears only on `status: ROLLED_BACK`. Absent means what 1.1 meant: no cause is reported, which a consumer reads as `UNKNOWN`.

- **Why it was missing.** `ApplyRegionCommitResponse` keeps `result` XOR `error`. A successful rollback has a result, so `error` is null, and `applyFailure` is legal only beside a restore error (`RESTORE_FAILED`). So 1.1 had no legal place for the failure that made Canvas restore. There is no region `QueryTransaction` (`world-adapter-region/v2` and `canvas-region/v2` have none). Per-cell `QueryTransaction` needs the prepared `transactionPayloadDigest`, which `operationDigest` does not replace. Adapter last-call facts are not durable. History/pending records hold no rolled-back transaction.
- **Rules** (`regionRollbackCause.rules`, all `SCHEMA_INVALID/INVALID_SHAPE` unless noted):
  - only on `ROLLED_BACK`;
  - `error.phase` is not `restore`;
  - `error.mutationState` is `NONE`, `PARTIAL` or `UNKNOWN` (the state at the failing step, before the restore);
  - `error.transactionRef` is `null` or the result `transactionId`;
  - a non-null `guardRefusal` explains `error` exactly (`guardRefusalError`);
  - a closed shape (unknown field `UNKNOWN_REQUIRED_FIELD`).

  The labels are the closed `ErrorCode`/`ErrorReason`/`GuardRefusal` values. No free text and no new enum value were added. An Adapter `WriteRegion` error and guard refusal that caused the restore are relayed unchanged. A failed restore keeps the 1.0 form (`RESTORE_FAILED` + `applyFailure`, no result).
- **Reading.** `regionRollbackCauseOf(request, response)` runs `validateRegionCommit` (same request, transaction, World, `localContext`, `operationDigest`), requires a `ROLLED_BACK` result, and returns `{requestId, transactionId, worldRef, localContext, operationDigest, cause: 'REPORTED'|'UNKNOWN', failure}`. It is pure and never writes. The route is the ApplyRegionCommit response itself. Canvas stores the terminal response with the request outcome, and an exact replay (`validateCurrentRequest` → `RETURN_STORED`) returns it unchanged without writing again. No query operation is added.
- **Capability and invariant.** `canvas-region/v2:rollback-cause` (owner Canvas): every `ROLLED_BACK` result carries the cause. A consumer that needs it requires the capability (`checkProtocolCompatibility` → `CAPABILITY_UNAVAILABLE` before any write when it is missing). Invariant `REGION-ROLLBACK-CAUSE-OBSERVED` (not switchable): the cause states only what the transaction owner observed in its own operation boxes. It never names natural simulation, other writers or test instrumentation, and an absent cause is `UNKNOWN`.
- **Not covered** (`regionRollbackCause.notCovered`): cells outside the operation boxes and natural simulation (neither restored nor attributed), `UndoRegionCommit` results (`rollbackCause` there is `UNKNOWN_REQUIRED_FIELD`), and who injected a test fault.
- **Recovery and observation scope (unchanged, stated for consumers).** The recoverable scope of a region transaction is the operation boxes. `beforeSummary` chunk boxes equal the operation `blockBox`es. `ROLLED_BACK` requires `actualSummary == beforeSummary`, and Undo `VERIFIED` requires the restored summary to equal the origin before summary over that same layout. Undo is attempted only while the current summary equals the verified after summary; otherwise it is `UNDO_CONFLICT/EXTERNAL_EDIT_CONFLICT`, and any change inside the boxes, natural or not, counts as that conflict. A wider `ReadRegion` (for example whole mapblocks) is an observation with its own digests. It is not a receipt, grants no restore right, and is not made equal to the before state by a VERIFIED Undo. Whether a product gate needs more than this is a product decision. The contract does not widen it.
- **Who adapts.** Canvas produces the field and advertises the capability. Consumers that read the cause call `regionRollbackCauseOf`. A 1.1 strict decoder refuses a result that carries the field (fail-closed), so every package in one assembly must resolve to 1.2 before Canvas emits it. With one physical contracts package and `^1.x` ranges, that is a lock change only.
- **Evidence.** `npm run test:rollback-cause` / `typecheck:rollback-cause` with `hanaworlds-contracts/fixtures/region-rollback-cause` (built by `tools/build-rollback-cause-fixture.mjs` from `fixtures/region`: 4 accepted cases, 11 named refusals). Every 1.1 suite is unchanged. Also `tools/cross-version-rollback-cause.mjs` (1.1 ↔ 1.2) and `tools/gate-region-rollback-cause-v1.2.sh`. All of this is SOURCE/PACK/FIXTURE only; peer implementations and real runtime are NOT_RUN.

## 1.1.0 · confirmed placement bound to the actual effect set (release 1.1.0)

**Change note (1.1.0, qualified additive minor; every 1.0 value, digest, wire and capability id unchanged):** a placement shown to the player before confirmation can be a structured `PlacementProposal` made from a real `RegionInspection`. When present it is part of the confirmed intent (`Controls.placement` → `ConfirmedIntent.placement`, digest-bound); Painter matches the final world effect set against it on the proposal and model paths; Canvas rechecks it before any write on both the per-cell apply (`RegionApplyBinding.confirmedPlacement`) and the region commit (`ApplyRegionCommitRequest.confirmedPlacement`). Absent means what 1.0 meant: no structured placement was confirmed.

- **Why a minor.** The four new fields are optional and have no null form; absence keeps the exact 1.0 meaning, so every 1.0 request, response, context and fixture stays valid byte for byte with the same digests; no existing field, enum, constant, wire or capability id changes; a 1.0 strict decoder refuses a value that carries a placement (`UNKNOWN_REQUIRED_FIELD`), so the capability fails closed and is never silently ignored. This is the qualified optional field of `protocolPolicy.minor`; `tools/compare-major.mjs` classifies each wire (`ADDITIVE` / `UNCHANGED` / `BREAKING`) and `tools/cross-version-v1.mjs` checks the 1.0 and 1.1 packages against each other. Who must adapt: only those that use the capability — Workshop (produces and binds), Painter (checks proposal/model paths), Canvas (checks before writes). Others keep `^1.0.0`.
- **Proposal.** `PlacementProposal {profileVersion:'placement-proposal/v1', worldRef, source:{inspectionId, anchorKind, worldRevision, targetFactsDigest, frameDigest}, target}`; `target` is `EXACT_CELLS {cells}` (sorted, unique, non-empty world cells: write exactly these) or `ANCHORED_EXTENT {bounds}` (a general building at a confirmed located range; cells inside are not individually confirmed). `createPlacementProposal(inspection, target)` is the only constructor; the target must lie inside that inspection's sampled bounds. Digest kind `placement-proposal` (domain `HanaWorlds|placement-proposal/v1|`). No player pose, body or yaw.
- **Confirmation.** Only a new human message confirms (unchanged Workshop rule). `confirmedPlacementOf(intent, brief)` requires `ConfirmedIntent.placement` to equal the shown `BriefProjection.controls.placement` (both absent, or equal).
- **Painter (painter/v5, painter-region/v2).** With a confirmed placement, `validateBuildProposalRequest` requires `request.regionInspection` to be the placement's source inspection (same World, frame, world revision, inspection id and facts digest) and the computed effects to equal the exact cells / lie in the extent; a new CURRENT_VIEW inspection never re-interprets confirmed local geometry. `validateCreateBuildPlanRequest/Response` give the model path the same promise (source inspection before any model call; planned operations cover exactly the cells / stay in the extent; a `ClarificationNeed` must answer this invocation). `validateRegionProposalRequest` matches the block's specified world cells.
- **Canvas (canvas/v6, canvas-region/v2).** `validateBoundRequest` checks an apply binding against the apply's own operations; `checkConfirmedPlacementApply(apply, recordedInspection, currentWorldRevision)` rechecks against Canvas's recorded inspection and current revision. For regions, `validateRegionCommitRequest` (also run by `validateRegionCommit`) checks the binding digest, World and every chunk's specified cells, and `checkConfirmedRegionPlacementCommit(commit, recordedInspection, currentWorldRevision)` runs before any snapshot or Adapter `WriteRegion`. Workshop must send exactly `confirmedPlacementBinding(intent)` (no field when none was confirmed): `validateCurrentBuildSubmission` and `validateRegionCommitSubmission(intent, brief, commit)`.
- **Named refusals** (`confirmedPlacement.namedFailures`; the thrown error also carries `placementFailure`): `PLACEMENT_TARGET_MISMATCH` (`INTENT_UNCONFIRMED/INVALID_GEOMETRY`), `PLACEMENT_BINDING_CHANGED` (`INTENT_UNCONFIRMED/IDENTITY_UNVERIFIED`), `PLACEMENT_INSPECTION_CHANGED` (`TARGET_FACTS_STALE/PAYLOAD_CHANGED`), `PLACEMENT_REVISION_STALE` (`TARGET_FACTS_STALE/REVISION_CHANGED`), `PLACEMENT_FRAME_CHANGED` (`INVALID_FRAME/PAYLOAD_CHANGED`), `PLACEMENT_WORLD_CHANGED` (`CURRENT_WORLD_MISMATCH/SCOPE_DENIED`), `PLACEMENT_OUTSIDE_INSPECTION` (`TARGET_FACTS_INCOMPLETE/INVALID_GEOMETRY`). All `validate`, `AFTER_NEW_FACTS`, nothing written: a new proposal and a new human confirmation are needed. No ErrorCode/ErrorReason value was added.
- **Validator mechanics.** The schema interpreter skips an absent optional property; digest projections omit absent optional fields (so 1.0 digests are unchanged); generated TypeScript marks optional fields with `?`. No 1.0 type has an optional field, so their behaviour is unchanged.
- **Unchanged.** Known-empty, body clearance, hazards, engine guards G1–G3, failure-without-write, whole rollback, CURRENT_VIEW frame and `entranceFacing`, building dimensions and site rules. Invariant `CONFIRMED-PLACEMENT` is listed (not switchable) in `placementInvariants`.
- **Evidence.** `npm run test:placement` / `typecheck:placement` with `hanaworlds-contracts/fixtures/confirmed-placement` (generated by `tools/build-placement-fixture.mjs`; 55 cases over proposal, model, per-cell Canvas and region Canvas paths), every 1.0 suite unchanged, and `tools/gate-confirmed-placement-v1.1.sh`. SOURCE/PACK/FIXTURE only; peer implementations and real runtime are NOT_RUN.

## 1.0.0 · skill site rules, no player geometry, named safety capabilities, engine guards (release 1.0.0)

**Change note (1.0.0, breaking major; 0.x has no compatibility, migration or dual version):** `requireEntranceConnectivity`, `entranceClearance`, `hazardPolicy` and `optionalLightRule` are skill-proposed and player-confirmed (`SiteRules` in `Controls.siteRules` → `ConfirmedIntent.siteRules`); `safetyProfileFromConfirmedIntent` is the only SafetyProfile source; no contracts type carries player geometry; light, region-entrance and engine checks G1–G3 are named capabilities with exact refusals. Changed wires: `session/v3→v4`, `ReferenceBrief/v3→v4`, `painter/v4→v5`, `painter-region/v1→v2`, `BUILD/V3→V4`, `canvas/v5→v6`, `world-adapter/v6→v7`, `world-adapter-region/v1→v2`, `canvas-region/v1→v2`, `safety-profile/v3→v4`; unchanged: `interaction-surface/v4`, `region-build/v1`, `operations/v3`, `target-facts/v4`.

- **Rules (A).** `SiteRules {requireEntranceConnectivity, entranceClearance, hazardPolicy, optionalLightRule}`: all keys required, values open (no enum, no default). `Controls.siteRules` is nullable until the skill proposes; `ConfirmedIntent.siteRules` is required and digest-bound by `referenceBriefDigest`/`intentDigest`. A request SafetyProfile that is not exactly `safetyProfileFromConfirmedIntent(intent)` is `INTENT_UNCONFIRMED/PAYLOAD_CHANGED`; a rule changed after confirmation breaks the intent digest. `requireBodyClearance` stays the non-switchable invariant (`true`).
- **Light.** A non-null `optionalLightRule` stays expressible and is refused with `CAPABILITY_UNAVAILABLE/validate/REQUIRED_FACT_UNKNOWN` (capability `painter/v5:light-rule`, cause `LIGHT_RULE_UNCHECKED`) at Painter admission and witness coherence: no light witness kind exists in this major. It is never silently accepted.
- **Entrance (B).** `requireEntranceConnectivity` needs a confirmed `entranceClearance` (`ClearanceCells`, whole nodes) — a building design value, not a player measurement and no proof that a real player fits. Confirmed portal refs must exist in `targetFacts.portals` (`TARGET_FACTS_INCOMPLETE`); with none, the entrance is the doorway on `regionInspection.entranceFacing` and `EntranceWitness.portalRef` is `null`; the witness `clearance` must equal the confirmed one. `painter-region/v2` has no entrance check: a confirmed entrance requirement is refused there by name (`painter-region/v2:entrance-rule`); hazards are checked per palette node.
- **No player geometry.** `SafetyProfile.avatarDimensions`, `RegionInspection.bodyOccupiedPositions`, `BodyWitness.{bodyOccupiedPositions,avatarDimensions}` and `EntranceWitness.avatarDimensions` are gone; `AvatarDimensions` is renamed `BuildDimensions` (building size only). Actual bodies are checked only inside the engine. CURRENT_VIEW frame and `entranceFacing` semantics are unchanged.
- **Engine guards (G1–G3, rc.2).** `PublicCapabilities.engineGuards` (`EngineGuardDeclaration`, `engine-guards/v1`, null for non-engine providers) states per guard (`BODY_CLEARANCE`, `CELL_PROTECTION`, `PLAYER_ENCLOSURE`) exactly which `EngineGuardStage`s the loaded payload checks (`INSPECT_REGION`, `PREPARE_RECOVERABLE`, `APPLY_COMPILED`, `PREPARE_HISTORY`, `APPLY_HISTORY`, `RESTORE`, `REGION_APPLY`, `REGION_RESTORE`; `engineGuards.stages` maps each to its public operation). A stage not listed is not covered. `CELL_PROTECTION` names its `protectionPrincipal`: `ANONYMOUS` (no caller identity, e.g. `core.is_protected(pos, '')`; refuses every protected cell for everyone; not acting-principal protection) or `ACTING_PRINCIPAL` (no identity source exists in this major). `unmetEngineGuards` / `requireEngineGuards` refuse uncovered stage/principal requirements pre-flight (`CAPABILITY_UNAVAILABLE/validate/REQUIRED_FACT_UNKNOWN`).
- **Guard refusals.** Every response a guard can refuse (`ScopedPrepareResponse`, `ScopedApplyResponse`, `PrepareHistoryTransactionResponse`, `ApplyHistoryTransactionResponse`, `RestoreTransactionResponse`, `InspectRegionResponse`, `WriteRegionResponse`, `ApplyRegionCommitResponse`, `UndoRegionCommitResponse`) and `ReceiptProjection` carry `guardRefusal {guard, stage, finding}` beside `error`; `guardRefusalError` gives the exact error. Findings `BODY_OCCUPIED`, `PROTECTED_CELL`, `PLAYER_ENCLOSED`, `GUARD_UNAVAILABLE` (at `RESTORE` = RESTORE_GUARD_UNAVAILABLE). At restore stages the error is `RESTORE_FAILED/restore/RESTORE_ERROR`, `AFTER_MANUAL_RECOVERY`, `PARTIAL`, and `causeCode` keeps naming the failure that made the restore necessary.
- **Refusals reach the skill (rc.4).** A guard refusal travels on the public wire all the way up: Adapter responses → Canvas responses (canvas/v6 `ApplyRecoverableCommit`, `Undo`, `Redo`, `RecoverPendingUndo`, `ReadPendingUndoResult`, `InspectPlacementRegion`; canvas-region/v2 commit/undo) → Workshop responses (session/v4 `AdvanceCurrentBuild`, `UndoCurrentBuild`, `RecoverPendingUndo`). Each of these envelopes now carries `guardRefusal` beside `error` under the same exact-error rule; a relay passes the refusal and its error unchanged, and Canvas's own pre-flight refusal is `GUARD_UNAVAILABLE` with `CAPABILITY_UNAVAILABLE/validate`. `engineGuards.relay` lists the chain. canvas/v6 and session/v4 identifiers are unchanged inside the candidate (already bumped from 0.5.6).
- **Restore refusals without a cause (rc.3).** A stateless engine restore write (`WriteRegion` purpose RESTORE, i.e. stage `REGION_RESTORE`, or any restore whose writer does not know why it restores, such as an Undo) reports a guard refusal in the engine form: `SAFETY_INVARIANT_FAILED` (violation) or `CAPABILITY_UNAVAILABLE` (`GUARD_UNAVAILABLE`), phase `restore`, `mutationState NONE`, `causeCode null`, reason as for other stages; `guardRefusalError(refusal)` without `cause` returns it. The transaction owner turns it into the pending transaction form (`RESTORE_FAILED`, causeCode = the causing failure, `applyFailure`) when it was a rollback, and returns it unchanged (`applyFailure null`) when it was an Undo. No type or field changed from rc.2.
- **Restore failure keeps both causes.** A `RESTORE_FAILED` receipt, and a region commit/undo response ending in a failed restore, carry `applyFailure {error, guardRefusal}` with the causing failure in full; `error.causeCode === applyFailure.error.code`; `restoreStatus` stays `FAILED`/`UNKNOWN`. rc.1's `world-adapter*:…` ProtocolHandshake capability ids and `safetyCheckFailure` are replaced by this; `safetyCapabilities` keeps only the light and region-entrance rules.
- **Evidence.** `npm run test:site-rules` / `typecheck:site-rules` with `hanaworlds-contracts/fixtures/skill-site-rules` (site rules, engine-guard declarations, refusals, restore-failure receipts), plus every earlier suite on the new shapes; `tools/gate-safety-v1.sh`. SOURCE/FIXTURE only; peer implementations, engine checks and real runtime are NOT_RUN.

## Same-major compatibility (0.5.6)

**Change note (0.5.6, minor-additive):** package compatibility is decided by major only. `checkContractHandshake`, `checkBuildProposalHandshake` and the new schema entry `checkSchemaCompatibility` all use one predicate, `checkContractsVersion`: same package name, well-formed semver, equal major; minor, patch and prerelease are provenance. Wires, `compiledOperationsVersion`, fact profiles, required types and capabilities are still checked separately, so a version match never implies an interface. No wire, operation, type, field, enum, ownership or digest domain changes. 0.5.6 also releases the `config-engine-facts/v1` addition from `0.5.5-rc.1` unchanged.

- **Consumers.** Depend on the contracts source by git tag range, `hanaworlds-contracts#semver:^0.5.6` (or the lowest tag carrying the fields you use). A later additive minor or patch needs no re-pin and no re-adaptation.
- **Rejected as before.** Another major, another package, malformed refs (`UNSUPPORTED_VERSION/decode/VERSION_UNSUPPORTED`); missing wire or fact profile (`UNSUPPORTED_VERSION`); missing required type or capability (`CAPABILITY_UNAVAILABLE`); bad shape or type (`SCHEMA_INVALID`); unknown fields such as authority (`UNKNOWN_REQUIRED_FIELD/UNKNOWN_FIELD`).
- **Protocol handshake.** `checkProtocolCompatibility` is unchanged: protocol major equality plus capabilities; `protocolRequirement` defaults `minMinor` to 0, so any minor of the major passes unless a consumer explicitly declares a structural minimum.
- **Old packages.** Code still running 0.5.5-rc.1 or earlier keeps its exact-package check against its own version; same-major acceptance applies on each side once it runs 0.5.6 or later.
- **Evidence.** `npm run test:major-compat` / `typecheck:major-compat` with the public fixture `hanaworlds-contracts/fixtures/contracts-major-compat` (SOURCE/FIXTURE). Peer implementations and real runtime are NOT_RUN.

## Config engine facts (0.5.5-rc.1 candidate, released in 0.5.6)

No wire, operation, protocol minor, existing type, field, enum value, ownership row or digest domain changes. The exact-package handshake means each composition re-pins one package.

- **Port.** `ConfigEngineFactsPort.readConfigEngineFacts(worldRef)` is an additive in-process method of the existing `hanaworldsLuantiNativeFacts` service, like `readMaterialSources`. It is not a wire operation, model argument, tool or persisted record.
- **Write backend.** `backendProfileId` names the write backend the loaded Adapter payload uses for `world-adapter/v6` scoped Prepare/Apply with `explicit-nodeName-param2-static-v2`, as declared by that payload. Adapter is the only producer. `adapterId`, `payloadVersion`, `capabilityRevision`, package/contracts versions or a default are not substitutes; `NOT_DECLARED_BY_PAYLOAD` / `ENGINE_FACT_UNREADABLE` otherwise.
- **No player geometry.** `avatarEnvelope` is always `{availability:'UNAVAILABLE', reason:'NO_PUBLIC_SOURCE'}`; it has no KNOWN form. Actual collision boxes, their extents, positions, yaw and posture stay inside the payload (INV-POSE-STAYS-IN-ENGINE). A consumer needing `avatarDimensions` refuses with `configEngineFacts.avatarDimensions.refusal` (`CAPABILITY_UNAVAILABLE`/`validate`/`REQUIRED_FACT_UNKNOWN`, cause `INV-POSE-STAYS-IN-ENGINE`) and persists no player geometry or SafetyProfile derived from it; defaults, a designed 1×2×1, values derived from live boxes and `ConfirmedIntent`/`Controls.dimensions` (building dimensions) are not substitutes. Prepare still rechecks bodies in the engine (INV-BODY-RECHECK-AT-PREPARE).
- **Consumer.** Canvas validates with `validateConfigEngineFacts(facts, freshCatalogue, currentConnection)`, takes the backend only through `requireKnownWriteBackend` and refuses avatarDimensions through `requireKnownAvatarEnvelope`. Brush, Painter, Workshop and Host are unchanged.
- **Domain and lifecycle.** Valid only for the exact `{worldRef, connectionRef, connectionIncarnationRef}` and `catalogueDigest`. `sourceRevision = digestValue('config-engine-facts', facts without sourceRevision)` in the domain `HanaWorlds|config-engine-facts/v1|`. A payload, Catalogue, connection or world change yields a new revision or a rejected read; players never change it. No push, so consumers re-read before each assembly.
- **Not decided here.** A public avatarDimensions source (product boundary), the four Stage1 policy values, `worldeditRevision` (already `Catalogue.modRevisions`) and every existing consumer meaning.
- **Evidence.** `npm run test:config-facts` and `npm run typecheck:config-facts` are SOURCE/FIXTURE conformance for both sides. Adapter provider, Canvas consumer and real runtime are NOT_RUN.

## Session–World seam (0.5.4)

**Release identity (0.5.4):** content of candidate `0.5.4-rc.1` (`0beeff5774db476c0128683ca6107a28bdcdcbee`) with the release version string; no type, operation, schema, fixture, validator or helper change against rc.1. Every composition re-pins exactly `hanaworlds-contracts@0.5.4`; rc.1 and 0.5.4 reject each other in the exact-package handshake.

**Change note (0.5.4, minor-additive; consumers re-pin together):** adds `session-world-seam/v1` as protocol minors inside the existing majors. `session/v3` minor 1 appends `ReadSessionIdentity` and `ListSessions`; `canvas/v5` minor 1 appends `UnselectWorldConnection`, `RetireSessionSelection`, `ListWorldSelections`, `ReserveWorldRetirement` and `ReleaseWorldRetirement`. 24 new types, 3 pure helpers (`requireWorldRetirable`, `describeSelectionConnection`, `requireSessionDeleteSupported`), the `sessionWorldSeam` metadata export and the public FIXTURE `fixtures/session-world`. No new wire; every existing operation keeps its position and every existing type, field, enum value (including `Readiness` and `ErrorCode`), ownership row and digest domain is unchanged. The exact-package handshake means each composition re-pins one package.

- **Authority.** Canvas is the only Session→World selection authority and the only source of `selectionRevision`. Workshop supplies trusted Session identity and coordinates deletion; trust comes from the Host-bound port, never from request JSON, and a syntax-valid `Ref` is not an existing Session. Adapter supplies readiness, connection incarnation and transport only; it keeps no Session→World table.
- **G-S** `ReadSessionIdentity` / `ListSessions` → `SessionIdentity{sessionRef,sessionRevision}` / `SessionDirectory{directoryRevision,sessions}` (sorted by sessionRef). Unknown or deleted: `SESSION_NOT_FOUND`. `sessionRevision` is Workshop's revision, the same value Canvas carries as `CurrentContext.sessionRevision`. Canvas reads it before `SelectWorldConnection`/`SwitchWorldConnection`.
- **G-U** `UnselectWorldConnection(sessionRef, worldRef, expectedRevision, expectedContext)` compares with the current selection and returns `CurrentContext` with `activeWorldRef:null`, `localContext:null` and no selected objects; the Session reads `UNBOUND` again.
- **G-D** `ListWorldSelections(worldRef)` → `WorldSelectionInventory{worldRef,inventoryRevision,sessionRefs,retirementReservationRef}`. Adapter deletion: `requireWorldRetirable(inventory)`, `ReserveWorldRetirement(expectedInventoryRevision)`, delete its own world, then `ReleaseWorldRetirement(RETIRED)` (or `ABORTED` on failure). A world still selected by any Session, or a selection of a world under reservation, fails with `TRANSACTION_CONFLICT`/`SCOPE_DENIED`; a retired world is `WORLD_NOT_FOUND`.
- **G-L** Only when the Workshop provider actually supports persistent deletion (`sessionDeleteSupported:true`, checked by `requireSessionDeleteSupported`), Workshop calls `RetireSessionSelection(sessionRef)` and then deletes. Otherwise `DeleteSession` fails with the existing `SESSION_DELETE_UNSUPPORTED`/`DELETE_SEAM_ABSENT`, Canvas is not called and nothing changes. `deleted:true` only after the provider's readback shows the Session gone; releasing or disposing live handles is not deletion. Retirement is irreversible and is never silently undone or reported as deletion.
- **Clarifications of existing meaning (no change).** C1: `ReadWorldSelectionContext.worldRef` names the inventory returned; `UNBOUND` means the Session has no current World, and a BOUND `activeWorldRef` may differ from the requested world. C2: a BOUND selection keeps the last actual `LocalWorldContext` (`BOUND` with `localContext:null` is invalid because `CurrentContext.activeWorldRef` must equal `localContext.worldRef`); connected-now is derived against Adapter's inventory by `describeSelectionConnection` (`CONNECTED` / `SELECTED_NOT_CONNECTED`), and a stale incarnation stays rejected for writes by `CURRENT_WORLD_MISMATCH`. C3: on native process exit Adapter removes the connection from `ConnectionInventory` and changes `capabilityRevision`; a reopened world gets a new incarnation. No `Readiness` value is added.
- **Not added.** A single atomic selected-object/objectRevision snapshot (zero/multiple selection rules) and an official Loader/provider recipe are open supply items, not part of this candidate. The existing typed route is `ReadWorldSelectionContext` plus `ListObjects` under the same `localContext`.
- **Evidence.** `npm run test:seam` and `npm run typecheck:seam` are SOURCE/FIXTURE conformance. Provider implementations (Canvas, Workshop, Adapter) and real runtime are NOT_RUN.

## Material fact scope on the write path · G3 (0.5.1–0.5.2)

0.5.0 required `hasCallbacks === false && hasPersistentState === false` (via `validateStaticMaterials`) without saying what those facts cover, so a careful Adapter had to assume every future player/ABM/LBM path and could prove nothing but `air`. 0.5.1 fixes the scope as **`write-path-init/v1`** (`writePathStateScope`). The validators are unchanged: `false` admits, `true` or `null` rejects, UNKNOWN is never defaulted to false.

- **Declared path `CALLBACK_FREE_NODE_DATA`.** Per-cell and region writes/restores set node name and param2 as bulk node data (Luanti VoxelManip `set_data`/`write_to_map`; param1 is recomputed light). The engine runs no node-definition callback and creates no metadata/inventory/timer on this path. The Adapter declares this with `world-adapter/v6:callback-free-write` and `world-adapter-region/v1:callback-free-write`, and that its Catalogue facts follow this scope with `world-adapter/v6:write-path-state-facts` (`world-adapter` and `world-adapter-region` minors are now 1).
- **Verifiable basis.** `WritePathEvidence` (`write-path-evidence/v1`) is the inventory a registry reader can actually observe: per node the names of callback fields defined on the registered definition (`definedCallbacks`, null if unknown) and `globalWriteCallbacks`, the engine global registries that fire on this path and have handlers (e.g. `register_on_mapblocks_changed`; null if unknown). `writePathStateFacts(evidence)` derives the facts mechanically:
  - `initializationCallbacks` (`on_construct`, `after_place_node`, `on_timer`, `on_destruct`, `after_destruct`): the node relies on lifecycle code this path skips → `hasCallbacks: true`, `hasPersistentState: null`.
  - `stateIndicatorCallbacks` (`allow_/on_metadata_inventory_*`, `on_receive_fields`, `preserve_metadata`): the node uses cell state → `hasPersistentState: null`.
  - otherwise `false/false`. Unknown definition inventory or revision, or a non-empty/unknown `globalWriteCallbacks`, makes every node `null/null`. Never `true` for persistent state from opaque Lua bodies.
  - `validateCatalogueWritePathFacts(catalogue, evidence)` binds the evidence to the Catalogue digest and definition revisions and refuses a Catalogue that is looser than the derivation (`CATALOGUE_MISMATCH`); stricter `null`/`true` is allowed and reported.
- **Out of scope, not claimed absent.** Player-triggered callbacks (punch/dig/rightclick/after_dig_node, global punch/dig handlers), ABM/LBM and other independent world dynamics, mod-private custom fields, and external effects of a replaced node's skipped destruct callbacks. Such later changes are caught by the complete `RegionState` readback (node, param2, extras) and its summary digest, and by same-transaction Undo rejecting with `UNDO_CONFLICT/EXTERNAL_EDIT_CONFLICT`. Canvas still decides every transaction.
- **Handshakes (0.5.2).** The G3 scope changes no handshake. `checkContractHandshake`/`checkBuildProposalHandshake` stay exact-package (0.5.1's same-0.MINOR-line acceptance is withdrawn: a package line proves no protocol or capability). Runtime interop between components on different package patches is decided only by `checkProtocolCompatibility` over each peer's `ProtocolHandshake` (wire major + required capabilities, e.g. `BUILD/V3` + `BUILD/V3:per-cell-compile`); package version, source and hash stay provenance.

## Region voxel block + palette v1 (0.5.0)

Additive only: all 334 earlier types, 55 operations, ownership rows, digest kinds, settings and invariants are byte-identical to 0.4.2 (`tools/compare-baseline.mjs`). Per-cell `BUILD/V3` → `operations/v3` is unchanged and remains the fine-adjustment path. No setting, threshold or scale limit is added; which write method to use is chosen by the skill from the tools' self-description.

**`RegionVoxelBlock` (`region-voxels/v1`).** `origin` is the min corner in world node coordinates (Luanti x,y,z, y up), `size` the positive x,y,z extent. `indexOrder` is `X_FASTEST_THEN_Y_THEN_Z`, i.e. `index = (x-ox) + sx*((y-oy) + sy*(z-oz))`, identical to Luanti `VoxelArea:index` and `.mts` schematic order, so Adapter maps directly onto VoxelManip data arrays. `palette` is `NodeSpec[]` sorted by UTF-16 `nodeName` then `param2`, unique, every entry used. `runs` is the canonical run-length form `[count, paletteIndex | null]` (adjacent values differ; counts sum to the cell count), so one content has exactly one encoding and one digest.

- `null` = **UNSPECIFIED**: the cell is not written and keeps node, param2 and extras. It is never carve.
- Carve is only the explicit palette entry `{nodeName:"air",param2:0}`. `ignore` (the engine's skip marker) is forbidden; `air` with param2 ≠ 0 is rejected; an all-null block is rejected.
- `validateRegionPalette(block, catalogue)` applies the same static-material rule as per-cell BUILD (known node, known definition, legal param2, no callbacks/persistent state) to every palette entry, air included.
- Helpers: `encodeRegionBlock`, `expandRegionBlock` (Int32Array, -1 = unspecified), `regionBlockBox`, `mapblockOf`, `regionChunksOfBox`, `expectedRegionState`, `summarizeRegionStates`, `expectedRegionSummary`. They are pure; no world access, compression or transaction decision.

**State and chunks.** Chunks are Luanti mapblocks (16³, `chunkEdge: 16`; an engine unit, not a policy). `RegionState` is a fully specified block (no null runs) plus sparse `extras` (metadata / inventory / timer per position) — the fields a restore needs beyond node/param2/air. param1 is derived light (`recompute-with-readback`). After a write, specified cells take the palette node and lose extras; unspecified cells keep everything (`expectedRegionState`). Region digests use the protocol domain `HanaWorlds|region-voxels/v1|<kind>|`, independent of the package version: `region-block`, `region-state`, `region-build`, `region-operations`, `region-summary`, `region-snapshot-content`.

**Flow (public seams; each role keeps its ownership).**

1. Painter `painter-region/v1 ValidateRegionProposal`: same Session/turn/intent/ReferenceBrief (media included)/Catalogue/localContext association as per-cell proposals; the result `RegionBuildProjection` carries the proposal block unchanged (`validateRegionProposalRequest/Response`). Painter validates only; it neither writes nor plans.
2. Brush `region-build/v1 CompileRegionBuild`: pure split into mapblock-aligned `RegionChunks` (`region-operations/v1`). `validateCompiledRegionSet` checks the chunks specify exactly the build's specified cells with the same node/param2, nothing outside the build box, and that unspecified never becomes air.
3. Adapter `world-adapter-region/v1`: `ReadRegion` covers every mapblock intersecting `box`; a chunk is `KNOWN` only after load (`ALREADY_LOADED` or `LOADED_BY_EMERGE`) and readback with a bound `stateDigest`; otherwise `UNKNOWN` with a reason. `requireKnownRegion` rejects any still-unknown chunk. `WriteRegion` writes per chunk after comparing `expectedCurrentDigest` (`APPLY` with ops, `RESTORE` with a full `RegionState`), returns per-chunk `WRITTEN/NOT_WRITTEN/UNKNOWN` + readback digest and a `RegionLighting` fact that is `COMPLETE` only after bulk light recalculation finished. `validateRegionWrite` returns `committed:false` always: Adapter never decides a transaction.
4. Canvas `canvas-region/v1 ApplyRegionCommit`: one logical transaction across chunks. `RegionCommitResult` is `VERIFIED` only when the complete `actualSummary` equals `expectedAfterSummary` and lighting is complete; `ROLLED_BACK` only when the actual summary equals the before summary (no residue). `RegionSnapshotRef` records the durable pre-write `RegionSnapshotContent` compressed with a mature format chosen by Canvas (`compression` name, compressed SHA-256 and length; the canonical JSON of the content is what gets compressed). `validateRegionSnapshotContent` checks content/state/summary digests after Canvas decompresses.
5. Canvas `UndoRegionCommit`: only for a `VERIFIED` origin transaction of the same world, only while the current region summary still equals the origin's verified after summary (otherwise `UNDO_CONFLICT/EXTERNAL_EDIT_CONFLICT`), and `VERIFIED` only when the restored summary equals the origin before summary.

**Protocol major + capability compatibility.** Each component advertises a `ProtocolHandshake` (`protocol-handshake/v1`): protocols `{protocol, major, minor}`, capability ids, and provenance (package name/version, source revision, artifact digest). A consumer builds `ProtocolRequirement`s (`protocolRequirement('canvas-region/v1', [caps], minMinor)`) and calls `checkProtocolCompatibility` before any write. Compatible = same major, advertised minor ≥ required, every required capability present. Provenance is returned for the record and never compared, so a different patch, source or hash of the same major interoperates. Missing protocol / different major / lower minor → `UNSUPPORTED_VERSION`; missing capability → `CAPABILITY_UNAVAILABLE`. Majors are explicit integers ≥ 1, independent of the 0.x npm version; a 0.x package version never implies compatibility, and a peer without a `ProtocolHandshake` (e.g. the exact 0.4.2 `ContractHandshake`) is rejected. Within a major, a minor may add operations, types or capability ids only; adding a field/enum value to an existing type is a new major. `contractProtocols`, `protocolPolicy`, `regionCapabilities` (id, owner, meaning) and `regionInvariants` (read-only, for the Shell management surface) are exported. No old wire/profile migration.

**Tool self-description.** `WriteMethodDescriptor` = method (`PER_CELL`/`REGION`), tool name, purpose, input type, free-text typical scale (`scaleUnit:"cells"`), required capability ids, unavailable reason. It has no threshold field by design.

**Public fixture.** `hanaworlds-contracts/fixtures/region` is an explicit hand-built SOURCE/FIXTURE scenario (fill, explicit carve, unspecified cells, 6 cross-mapblock chunks, emerge-loaded read, per-chunk write with lighting, gzip snapshot, VERIFIED commit and whole Undo, a peer handshake, two write-method descriptors). No real Painter, Brush, Adapter, Canvas, Luanti world or durable store ran to produce it.

## Local association and dispatch

`LocalWorldContext` contains the actual `connectionRef`, transport-open `connectionIncarnationRef`, selected `worldRef`, and Canvas world-selection `selectionRevision`. Adapter creates a new incarnation for each opened connection. Canvas changes the selection revision on connection/world reselection. These values correlate transport and business state; they convey no privileges, identity claims, permission, or delegated right. Read the actual connection through `ReadLocalConnection`; select using `SelectWorldConnection` with `expectedContext` (null for initial selection). `validateWorldSelection` compares the requested world/connection/incarnation to that readback. `ReadWorldSelectionContext` remains callable before a world is selected. Never invent a default incarnation.

World-bound requests carry `localContext`. Providers run strict `admitRequest` / `validateBoundRequest` and `validateCurrentRequest` using their own current state. The latter returns `EXECUTE` or `RETURN_STORED`; a completed duplicate returns the recorded outcome and cannot cause a second write. Provider storage owns durable reservation and outcome persistence. `LocalRequestFacts` is an internal function argument read from provider state, never a client credential or model tool payload. Current turn/brief and current connection must be re-read before consuming a result. No serialized value establishes live truth.

The Host binds internal ports: model → Workshop proposal tool → Painter → pure Brush → Canvas. Adapter mutators are exposed only on the internal Canvas dispatch port. Contracts describe this ownership and check payloads; they do not authenticate transports or enforce process access. A `callerRole: "Canvas"` field is not a substitute for internal dispatch and is not accepted. Painter and Brush never write the world; the model cannot invoke Adapter mutators.

## Build and transaction flow

1. Workshop supplies the current confirmed brief, bounded proposal context and live local facts. Painter calls `validateBuildProposalContext`, performs its BUILD construction, then `validateBuildProposalResponse`. Protected-region and game-privilege checks are absent. Physical body clearance, coverage, materials, hazards and geometry remain. Placement uses `CURRENT_VIEW` or a `PICKED_POINT`; online-user authorization and named-player choice are absent.
2. Brush consumes `BUILD/V3`, validates exact effects, and returns `operations/v3`. The declared BUILD, frame, catalogue, facts, safety and compilation digests must match. Contracts do not run a compiler.
3. Workshop uses `CurrentBuildSubmission` / `validateCurrentBuildSubmission` to correlate the current advance, intent, Canvas affected-object analysis and apply request. This replaces the former authorization derivation. Existing-object conflicts reject this fresh-build entry. Canvas owns further decision, registry, inspection-record and revision checks.
4. Canvas reserves a single transaction, reads real occupied footprints, and passes `ScopedWorldBinding` to Adapter prepare/apply. The scoped payload binds the exact local context, operation, checked cells, existing object footprints and saved before image. `projectScopedPreparedTransaction` projects the prepared result for apply. Caller-supplied prepared state is forbidden at the Canvas apply port.
5. Canvas obtains actual complete readback. `validateCommitReadback(receipt, expectedReadback, actualReadback, durableHistory)` checks equality, digest and same-transaction durable history. The expected state must come from Canvas/Adapter compilation or the saved before image, actual state from Adapter, and history from Canvas's durable store. For rollback, compare the complete saved before-state readback and pass null history. Pending/unknown is not verified success. These pure checks never prove real reads or durable persistence themselves.
6. History Undo retains the original transaction, saved before image, before/after readback digests, current state and history revisions. Workshop `UndoCurrentBuild` resolves the current verified build; Canvas owns same-transaction Undo, conflict checks and durable linked history. Adapter only transports it. Existing recovery shapes remain available for future work, but RPC recovery, timeout reentry, concurrency and extensive counterexample matrices are deferred and are not tested by this MVP gate.

## Readonly material sources (0.4.2)

`MaterialSourceFactsPort.readMaterialSources(worldRef)` is an additive in-process method of the existing `hanaworldsLuantiNativeFacts` service. It returns `{snapshot, textures}`. `snapshot` is strict JSON, `textures` is a list of `{bytesDigest, bytes: Uint8Array}` containing exactly one blob per distinct KNOWN digest. It is not a model argument, MediaBinding, Resource or mutating wire. No wire operations changed.

Host calls `validateMaterialSources(response, freshCatalogue, freshConnection)`; `freshConnection` has exactly worldRef, connectionRef and connectionIncarnationRef, projected from its current selection. The pure check binds the Catalogue digest/game identity, exact node name/definitionRevision/legal param2, sourceRevision, raw SHA256 and byte length. It cannot attest a runtime provider, decode an image or establish currentness by itself. Adapter must inspect the actual paired world/incarnation before and after its read, resolve the actual server game/mod texture source, and return a coherent snapshot or fail on connection/source changes. Host must recheck current selection and fresh Catalogue before consuming or caching the result. A persisted JSON snapshot alone is insufficient.

`sourceRevision = digestValue('material-sources', projection).sha256`, where projection is the snapshot with only sourceRevision removed. Rows are sorted by UTF-16 nodeName then numeric param2, with null first; duplicate keys are invalid. The digest includes source paths/names and actual byte digests, so changed bytes invalidate the revision even when the node registry revision stays constant. `sourceRef` is the resolved logical game/mod origin (for example `fixture-mod/textures/fixture_stone.png`), never a credential or public URL. Shared identical bytes may serve multiple rows. Omitted nodes have no known material source and must not be guessed.

KNOWN means the provider has verified an identical, unmodified, non-animated texture on all rendered faces, resolved source precedence and no appearance-changing animation, tint, palette, overlay or modifier. The source basis is explicitly SERVER_ASSET_ONLY: no claim about client texture packs or personalized rendered appearance. Any unverified source, override or effect is UNKNOWN with a reason and null texture; unknown legal param2 and definitionRevision remain null, never guessed as zero or a registry fallback. A non-null param2 always belongs to Catalogue.allowedParam2. PNG/JPEG/WebP byte formats still require Painter decoding. Unsupported rendering stays UNKNOWN; no renderer or RGB values are supplied here.

KNOWN describes texture provenance only. It never fills unknown static capability fields or authorizes a build. Painter must still run `validateStaticMaterials` on candidates; Canvas and Brush retain their existing validation. UNKNOWN/no usable static candidate produces an explicit unavailable result, not a fixture alias, default color or external game match. Adapter supplies actual bytes; Painter reuses its existing pure measurement; Desktop connects current facts; Workshop preserves media and confirmed material inputs. Canvas/Brush only update the exact shared image pin/handshake. No peer imports or peer code changes ship here.

Validation returns frozen JSON/records and owned copies of the byte arrays. Typed array elements remain mutable: decode those copies or revalidate after editing them; do not treat the returned wrapper as immutable pixel storage. JSON serialization is only for the snapshot, never the byte envelope.

Run `npm run test:materials`, `npm run typecheck:materials`, and `npm run verify:source` after build. `tools/gate-material-sources.sh FULL_SOURCE_SHA ABSOLUTE_EVIDENCE_DIR` verifies a clean archived source, deterministic generation, an actual tarball and an independently installed typed consumer. This is SOURCE/FIXTURE evidence; actual Adapter/Luanti and product UI gates belong to their writers.

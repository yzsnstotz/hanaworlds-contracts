# Contracts v4 (0.3.0) against approved `3.0.0-rc.8`: open contract gaps

Status: `SOURCE/FIXTURE`. Input: approved BlueMap `3.0.0-rc.8` (candidate `38687f19ff64b6fbff9da549015f2505eeff397a6d37c8e358f36a7b3764b41a`, core `ae95aca6f7a5aa143fb7be3056ba29027a02fa94a6c13ad1a638ad2c72656173`, closure `595209a4bdd78d8a188ec41ba7a9b8bf6aedfb38982a43c813b0189d10731747`), pinned in `spec/v4/APPROVED_INPUT.json`. The implementation follows the approved rows; it does not choose new semantics. Each item below is reported to the PM, who owns any erratum. Line references are to `spec/v4/`.

- **CONTRACT_GAP-V4-01 (Q1, known).** `CONTRACT_RULES.md:148` and `CONTRACT_SCHEMA_PROFILE.json:2049`: the condition under which `regionInspectionBinding` is required ("when `operations.targetFactsDigest` equals the digest of any REGION_INSPECTED record Canvas holds") is ambiguous. Implemented as approved: the field is required and nullable; with a non-null binding, `validateBoundRequest` checks only payload-carried coherence (`D(build)=operations.buildDigest`, `build.targetFactsDigest=operations.targetFactsDigest`, `D(build.coordinateFrame)=operations.frameDigest`) → `PERMISSION_DENIED/authorize/IDENTITY_UNVERIFIED/NONE`. The record-dependent condition belongs to Canvas and is not decided here; the approved reference oracle passes.
- **CONTRACT_GAP-V4-02.** `fixtures/candidate/placement-region-chain-v4.json:5818` (`SCHEMA-CHOICE-WITH-POSITION`) expects `SCHEMA_INVALID/decode/UNKNOWN_FIELD` for an unknown choice field. Every approved operation-fields oracle (for example `IS-01-INVALID`, `WA-01-INVALID`) and the strict decoder map an unknown field to `UNKNOWN_REQUIRED_FIELD/decode/UNKNOWN_FIELD`. The package keeps that mapping; phase and reason match and the message is rejected. The approved checker asserts only rejection.
- **CONTRACT_GAP-V4-03.** `CONTRACT_RULES.md:134` and fixture `INV-V021-CONSUMER-REGION-SOURCE` (`:5589`) say a contracts@0.2.1 decoder rejects REGION_INSPECTED facts with `SCHEMA_INVALID/decode/INVALID_SHAPE`. The admitted 0.2.1 decoder (the unchanged v3 lane) rejects them at decode with `UNSUPPORTED_VERSION/decode/VERSION_UNSUPPORTED`, because `profileVersion: target-facts/v3` is an unknown version constant and is checked before `source`. The behavior the rule protects holds (decode rejection, never treated as PLANNED, zero writes); only the code differs, and the admitted 0.2.1 bytes cannot change.
- **CONTRACT_GAP-V4-04.** Fixture `INV-FORGED-EVIDENCE-AT-APPLY` (`:2843`) changes `operationDigest` but keeps the valid chain's `authorizationBinding` (and its digest). The inherited binding-coherence check therefore rejects it first with `CONNECTION_UNAUTHORIZED/authorize/SCOPE_DENIED` instead of the expected `PERMISSION_DENIED/authorize/IDENTITY_UNVERIFIED`. With the binding re-bound to the forged digest, the package admits the payload and only the Canvas record match rejects it, as the approved checker's comment intends. Note: `CONNECTION_UNAUTHORIZED` is not in the `canvas/v4` `ApplyRecoverableCommit` allowlist; that helper behavior predates v4.
- **CONTRACT_GAP-V4-05.** The approved valid chain's Adapter requests use `actorRef: canvas-service-principal` while `authorizationBinding.actorRef` is the end-user actor (for example `prepareRequest`, `:1482`). The inherited `validateBoundRequest` required these to be equal and would reject an approved valid message. In the v4 lane only, the equality is not applied to `world-adapter/v4` requests, whose caller is Canvas only (`CONTRACT_SCHEMA_PROFILE.json:3379`, "caller is Canvas only"; operation orders "trusted Canvas domain"). Session, world, transaction and operation-digest equality are still enforced; Canvas-facing wires keep the actor equality. Consumers affected: luanti-adapter-v4, canvas-v4.
- **CONTRACT_GAP-V4-06 (phase and retryability details).** (a) REGION_INSPECTED fact-domain failures are `decode` phase, as `INV-REGION-SOURCE-WITH-OBJECTREF` requires; the inherited INSPECTED/PLANNED nullness failures keep their 0.2.1 `validate` phase (the approved checker's oracle uses `decode` for both, but no fixture exercises INSPECTED/PLANNED). (b) In the v4 lane `NON_CANONICAL_AMBIGUITY/validate/PAYLOAD_CHANGED` carries retryability `NEVER`, as the rc.5 digest-allowlist and rc.8 `INV-INVENTED-FRAME` oracles pin; the v2/v3 lanes keep their phase-derived `AFTER_NEW_FACTS`. (c) The Apply region-evidence rejection carries `AFTER_NEW_FACTS`, as the `CAV4-APPLY-REGION-EVIDENCE` fixtures pin, although the profile's generic authorization mapping (`:5131`) names `AFTER_NEW_AUTH`.

Observation, not a gap: `closure-oracles-v4.json` keeps 40 inherited IS/PA cases under their retired wire labels (`interaction-surface/v2`, `painter/v2`), byte-identical to the legacy file. `test/v4.mjs` checks that identity and replays each on its successor wire through the v4 lane; the legacy suite still runs them on v2.

Re-versioned existing assertions (package `0.2.1` → `0.3.0`, no behavior change): `test/v3.mjs` (`V3.version`; the v3 schema `$id` stays pinned at 0.2.1), `test/local-repair.mjs` (artifact identity), `tools/verify-source.mjs` (v3 runtime version) and `consumer/v3-run.mjs` (installed package version). All 558 legacy conformance cases keep their outcomes.

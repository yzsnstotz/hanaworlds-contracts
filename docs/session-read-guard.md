# C-session host-local read guard

`session-read-guard/v1` adds two methods on the existing `hanaworldsWorkshop` service: synchronous `captureSessionReadGuard(scope)` and synchronous `isSessionReadGuardCurrent(guard, scope)`. Existing asynchronous session/v5 ReadSessionIdentity and all wire operations keep their semantics. These methods are not JSON/HTTP operations and do not change session/v5 wire minor or advertise supported capability.

A supported provider must bind an opaque, nonserializable, exact-instance guard to the real official Session lifecycle, SessionStore provider, persistence provider, Workshop provider and committed projection provider. Its snapshot carries official sessionRef, committed Workshop sessionRevision and active world (null when unbound). Capture establishes reliable invalidation before any asynchronous preparation. Changed revision/world, disposal, deletion, unload, provider replacement, replacement Session and ABA irreversibly invalidate that exact guard. Checking another Session/world/revision or a foreign/fabricated guard returns false. A failure ends the read: no retry, reset or recapture to finish the same read.

After the consumer's last await, check Session, connection and Canvas local state together in the same JavaScript execution segment, with no await or callback that mutates providers between checks and return. No provider check invokes consumer selection, inspection or writes. Connection providers independently implement the same synchronous, monotonic observation semantics through their own public contracts; no private shared state or cross-module imports. This protocol does not assert that an Adapter implementation has been delivered.

DSH 0.2.0-rc.2 live SessionStore.get is synchronous and Session events have synchronous publication. JSONL SessionPersistence.stat/list/open are asynchronous, with no public synchronous currentness or complete monotonic invalidation covering direct storage handles and external artifact replacement. WorkshopProjectionStore.get also prepares its committed table asynchronously and does not publish a synchronous invalidation boundary. Those gaps prohibit issuance. A live log length and file stat revision cannot substitute. The fixed Workshop implementation returns CAPABILITY_UNAVAILABLE with concrete missing guarantees, even when a caller supplies purported support or a guard. It creates no Session, initializes no projection, opens no persistence handles and takes no locks.

The same prerequisite applies to settings-page Session identity/current-world reads, planned current Session snapshots, turn details and undo-status reads whenever they claim whole-preparation stability. Their ordinary wire snapshot semantics remain unchanged. ListSessions additionally needs a directory-wide official invalidation guarantee; this scoped protocol alone does not provide that. UI code must surface unavailability when asking for stable reads and must not present old asynchronous samples as stable settings.

Public `fixtures/session-read-guard` and `createUnavailableSessionReadGuardFixture` model this unsupported official capability. They never return a successful or constant-true guard and prove no supported stability. A future supported implementation requires controlled real-provider interleavings, including final-await changes and ABA, before it can advertise success.
